Short step-by-step (what happens when a request hits an endpoint):
1.
FastAPI security_scheme (HTTPBearer) reads Authorization: Bearer <token> header.
2.
get_current_user extracts token and calls _decode_token().
3.
_decode_token uses jose.jwt.decode with RSA public key + settings to validate signature, exp, aud, iss. If invalid → 401.
4.
On valid token, token_payload (includes guid and perm_version) is returned.
5.
get_current_user calls permission_service.resolve_permissions(token_payload).
6.
resolve_permissions reads cached_permissions = redis_service.get_user_permissions(user_guid).
7.
If cached_permissions exists AND cached_permissions.version == token_payload.perm_version → return cached (cache hit).
8.
If missing or version mismatch → call auth_service_client.fetch_user_permissions(user_guid) (HTTP call to Auth Service).
9.
If auth service returns permissions → redis_service.set_user_permissions(user_guid, permissions) (setex, TTL 7200s) and return them.
10.
If auth service fails (or cache/redis errors) → resolve_permissions returns empty PermissionResponse → get_current_user fails closed (503).
11.
get_current_user builds CurrentUser (includes permissions, perm_version) and returns it.
12.
Route guards (require_permissions/require_groups/require_admin) check CurrentUser.is_admin or CurrentUser.has_permission/has_any_group; missing → 403.

•
